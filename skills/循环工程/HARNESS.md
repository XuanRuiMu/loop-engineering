## 修改分级

|级别|范围|要求|
|---|---|---|
|自动|纯说明、示例、拼写和不改变契约的格式修正|先备份，修改后运行相关回归|
|待确认|状态字段、返回格式、测试清单、预算字段或风险流程|说明影响并取得用户确认后修改|
|禁止自动|主流程、默认权限、高危确认、熔断默认值、核心Skill契约|必须取得用户明确授权|

## 修改流程

1. 读取本清单和受影响的权威文件。
2. 建立可恢复备份。
3. 只修改本次授权范围。
4. 更新对应测试和README。
5. 运行 `python -B references/harness-test-suite/run_all.py`。
6. 检查实际文件、编码、Markdown格式和无意的旧契约残留。
7. 验证失败立即恢复，不保留半成品。

## 完整性边界

- `manifest.json`中的验证脚本哈希能发现单文件误改，但不能阻止同时篡改manifest和脚本的协同变更。
- 此类协同变更必须由独立审查者复核，并以外部版本控制提交或签名作为权威锚点。
- 10项离线回归只证明文档契约和验证器行为，不证明真实模型在任意宿主上的行为，也不证明弱模型经此达到高能力模型的推理效果。

## 验证入口

唯一全量入口：

```bash
python -B references/harness-test-suite/run_all.py
```

任务集合由 `manifest.json` 固定。空任务集、缺任务、缺脚本、未登记任务和任何子任务失败都必须返回非零。
