# 循环工程环境工程

本文件定义跨宿主的权限、风险、证据和交互原则。循环工程不绑定任何宿主的工具名、函数参数或代理类型。

## 1. 宿主能力适配

先识别能力，再选择等价实现。文档只规定语义结果，不规定调用语法。

|能力|有该能力时|没有该能力时|
|---|---|---|
|独立代理|把统一提示词交给新的隔离上下文|主代理串行补位|
|并行代理|同时派发无冲突任务|按顺序执行|
|用户交互|使用宿主提供的提问或选项能力|在普通回复中写清问题、选项和影响|
|版本控制|使用仓库实际提供的比较、暂存、提交和回退能力|使用文件清单、哈希和快照差异|
|后台任务|使用宿主后台机制并在返回前回收|同步执行，不遗留后台进程|
|token统计|记录宿主返回的真实值|保持未知|
|步骤限制|读取实际限制|不猜测数值，仅使用派发前估算|

提示词可以要求“启动独立代理”“并行启动审查角色”，但不得嵌入某个宿主的私有函数签名、固定类型名或参数名。

## 2. 权限与风险

### 默认权限

智能体默认拥有完成当前任务所需的最高项目权限，可以按任务读取、创建、修改当前项目内文件并运行验证命令。权限本身不因路径名称阻止工作，也不设置白名单或黑名单。

“最高项目权限”不等于突破宿主沙箱、访问项目根外系统或绕过宿主确认；这些硬边界继续生效。凭据和生产相关能力同时遵守项目级最小权限原则与本文件高危确认。

范围边界仍用于防止过度烘焙：智能体可以拥有权限，但不得执行用户目标之外的工作。

### 用户WIP

循环启动时已经存在的用户修改属于用户WIP：

1. 使用可用版本控制能力记录基线；没有时记录关键文件清单和哈希。
2. 在 `PROGRESS.md` 的“用户WIP”中只保留当前受保护路径。
3. 不回退、覆盖、格式化或顺手修复这些改动。
4. 用户WIP导致验证失败时，报告环境限制并交主代理处理。
5. 用户提交、撤销或明确纳入任务后，立即更新或删除对应WIP记录。

### 高危操作

普通读取、编辑、测试和构建无需逐项请求许可。以下操作必须先用通俗语言说明，再通过可用的用户交互能力取得确认；没有交互工具时，在普通回复中给出待确认项并停止相关操作：

- 写入、打印或提交凭据、私钥、令牌等敏感信息。
- 操作生产环境、远程服务器、外部系统或真实用户数据。
- 执行不可逆删除、数据库破坏性迁移或大规模数据转换。
- 改写核心代理规则、Skill契约、权限边界或发布流程。
- 强制推送、重写版本历史、丢弃未提交改动等破坏性版本控制操作。
- 依赖主版本升级、运行时替换或全局工具链变更。

提醒必须包含：

1. **要做什么**：用普通人能理解的话说明具体动作。
2. **为什么做**：说明与当前目标的关系。
3. **可能影响**：指出最可能受影响的功能、数据和环境。
4. **如何恢复**：说明备份、回退或恢复步骤。

风险确认只约束高危动作，不把普通项目开发变成逐文件审批。

## 3. 状态与产物

### 状态文件

`PROGRESS.md` 由主代理独占写入，是当前快照而不是历史档案：

- 初始不存在时先创建。
- 每轮覆盖更新。
- 完成项立即删除。
- 过期、重复、失效信息立即替换或删除。
- 可选节为空时整节删除。
- 正常任务建议40至70行，不为凑行数填充。

### 证据

需要保留证据时使用当前项目中的 `.agents/evidence/`：

```text
.agents/evidence/
├── traces/
├── proposals/
└── validations/
```

规则：

- `traces/`：验证轨迹摘要、必要片段和推理决策卡。
- `proposals/`：Harness改进提案。
- `validations/`：提案验证结果。
- 原始证据必须是真实文件。
- 链接使用 `.agents/evidence/` 下的相对路径。
- 禁止绝对路径、URL、路径穿越和指向目录。
- 不把完整日志复制进 `PROGRESS.md`；只保存一个链接或一条可复现命令。

推理决策卡按 `references/推理增强.md` 的命名和清理规则处理：功能点验收通过、结论被推翻或被更高序号卡片取代时立即删除；运行结束时不残留上一任务的决策卡。

没有证据文件时，在Worker摘要中写“证据：无”，并在验证字段给出命令和目标。主代理执行后决定是否需要落盘。

### 备份

- 普通说明或格式修改可以在修改前创建可恢复备份。
- 核心规则、预算、权限和返回契约修改必须有可恢复备份。
- 使用版本控制时可用仓库原生能力；没有时将待改文件复制到 `.agents/evidence/validations/backup-<时间戳>/`。
- 备份只保留到本轮验证和交付完成，随后清理；中断时保留并在交付中说明。
- 验证失败立即恢复备份，不保留失败版本。

## 4. 预算

预算字段、计数口径和熔断动作统一以 `BUDGET.md` 为准。本文件不重复默认值。

所有实际代理实例都要计数，包括嵌套审查代理。宿主不提供统计时保持未知，不使用猜测值。

## 5. 用户交互

### 交互模式

- 需求、范围、方向、权限、高危操作或完成交付需要决定时，使用宿主可用交互能力。
- 提问应说明背景、选项、推荐项和影响，避免只问“是否继续”。

### Headless模式

独立代理和其调用的专项Skill统一使用 `headless_mode=true`：

- 不直接向用户提问。
- 不替主代理做最终交付。
- 需求、方向、权限或高危决定返回“待用户确认”。
- 测试、审查、翻译、安全和验证要求保持不变。
- 所有未决项必须交主代理，由主代理使用宿主可用交互能力处理。

## 6. Headless决策返回

```text
状态：待用户确认
问题：<用户需要决定的一件事>
背景：<为什么现在必须决定>
选项：<选项A；选项B>
推荐：<推荐项及理由>
影响：<各选项对范围、风险和恢复的影响>
证据：<文件行号或命令输出>
恢复：<决定后从哪里继续>
```

- [ ] 用户WIP没有被覆盖。
- [ ] `PROGRESS.md` 只保留当前信息，完成项和失效项已删除。
- [ ] 代理实例、修复、stall、补位和墙钟计数符合 `BUDGET.md`。

- [ ] 证据路径真实、可解析且位于证据目录内。
- [ ] 最终门由主代理串行执行。
