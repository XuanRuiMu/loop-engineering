# PROGRESS.md 模板

循环工程的精简状态文件。只保存当前推进所必需的信息；已完成项只留一行摘要；不写历史、过程、文件清单。

---

### 状态说明

- **待开始**：尚未派发子代理
- **进行中**：子代理正在执行
- **已阻塞**：子代理无法解决
- **已完成**：验证通过并完成三轴审查，压缩为一行摘要移入"已完成"小节
- **已跳过**：因依赖阻塞或熔断跳过
- **已阻塞（环境）**：验证遇环境限制（⚠️），不计熔断；由主代理判定是否可绕过
- **已阻塞（方向性）**：实现中触发方向性假设拦截，待用户裁决

## 压缩规则

1. 功能点一旦变为"已完成"，除一行状态摘要外，删除该功能点的详细验收标准、涉及文件、历史记录、备注
2. "已完成"小节每行不超过一行，格式：`{ID} 已完成：{一句话摘要}`
3. 不写入"循环历史摘要"、"修改文件清单"、"详细决策日志"
4. "当前决策"只保留对待处理功能点仍有影响的条目；已落实或已失效的决策立即删除
5. 每轮更新后立即删除因状态变化而失效的内容
6. 『契约变更』节仅保留尚未被所有消费者吸收的增量行；消费者全部完成后立即删除该行；若消费者已"跳过"或"阻塞"且不再消费该 delta，亦删除或标注失效，不视为历史内容
7. 『视觉基线』节仅保留待处理 FP 相关行，随 FP 完成同步删除，不保留历史截图引用

## 填写要点

1. **停止条件必须可机器验证**：不能写"代码优化好了"，要写"所有测试通过且lint零报错"
2. **功能点粒度要粗**：一个功能点 = 一个完整可验证单元，不要拆得太细
3. **循环计数器要准确**：每轮循环+1，用于判断是否触发总循环熔断；若本轮并行派发多个无依赖/无文件冲突的子代理，仍只计 1 轮（Orchestrator 一次循环周期）；**每轮更新 PROGRESS.md 时立即递增，禁止把多轮攒到波次结束时一次补记**（计数滞后会直接架空 `total_turn_limit` 与 stall 上限）
4. **只保留当前状态**：PROGRESS.md不是历史档案，不存过程
5. **H1 标题反映当前任务目标**：PROGRESS.md 的 H1 标题应随任务目标变化，回归测试不得对标题文字做精确匹配
6. **计数两处一致（含补位）**：元信息『循环计数』== 熔断上限表『总循环次数』的"当前"列；元信息『补位计数』== 熔断上限表『主代理补位次数』的"当前"列。主代理每次写完 PROGRESS.md 后自检这两对数值，不一致即为漏记（`orchestrator_backfill_limit` 靠右列触发，右列不更新则补位熔断形同虚设）
7. **同一 ID 只允许一行**：『待处理功能点』『契约变更』『当前决策』『阻塞与遗留问题』各表内，同一 ID（FP-xx / L-xx / EV-xx）不得出现两行；状态变化时**就地改写**该行，禁止另起新行（两行矛盾状态会让下一轮派发依据失效）
8. **派发依据必须引用真实存在的 ID**：提示词中引用的 L-xx / V-xx / FP-xx 必须先 grep 确认在本文件内命中；未登记的改写成"未登记（口头补充）+ 原文"，禁止编造编号（见 `references/子代理提示词模板.md`『派单引用可解析性』）

## 并发写者登记（同树存在任何第二写入者/门禁持有者时启用）

启用判据（三条任一成立即须建本节，不得仅理解为"用户在并行改代码"）：①同一时刻存活 ≥2 个工人；②工人存活期间主代理自己也跑或后台挂着 build/test/lint/dev-server；③存在用户/其他会话的并行写入。

```text
## 并发写者登记

| 写入者 | 身份 | 活跃时段 | PROGRESS.md 写入者 | 我期间观察到的他人写入 |
| ------ | ---- | -------- | ------------------ | ---------------------- |
```

- 用途：本轮实测中，用户自己的并行功能点与循环工人在同一工作树、同一 PROGRESS.md 上交错写入，
  导致"某工人报告的绿色只是时点快照"与"他人迁移/配置改动被误算进本任务"两类误判。
- 规则：①工人开始时登记自己的 FP-ID 与时段；②交付/波次复跑必须由主代理在**无工人存活**时做一次；
  ③凡"禁止触碰"的他人文件，工人只观察不修改；④FP-ID 与波次表不符（出现未登记的编号）视为越界写入，立即上报。
- 规则（并发门禁与单写者，2026-09-21 元循环补）：⑤**同一工作树同一时刻只允许一个门禁持有者**——主代理自己启动的后台 build/test/lint/dev-server 未回收前，禁止再次跑门禁、也禁止另派工人；工人返回前必须回收自己启动的全部后台任务（`references/子代理提示词模板.md`『后台任务已回收』字段）。争用会产出**假失败**，据此判工人"假完成"属误判。
  ⑥**PROGRESS.md 单写者排他**：一旦本轮并行派发 ≥2 个工人，本节登记表必须显式写明"PROGRESS.md 写入者=主代理（工人只读）"，本轮工人对该文件的写入权即刻作废；单点派发且无他人写入时，工人才可自行更新该功能点状态行。注意：SKILL.md『子代理（Headless Worker）内部流程』第 6 步仍写着"更新 PROGRESS.md"，与本条存在文件级冲突；本条只在**已启用本节并显式登记单写者**的任务内生效，正式消除冲突须改 SKILL.md（禁止自动级，已记 EVIDENCE EV-030 待用户裁决）。
  ⑦"绿色只是时点快照"的复核口径：某工人摘要的绿，只在**其后无人再写入**时有效；下一轮派发前主代理须确认本节无新增活跃写入者，否则复跑门禁后再判树态。
- 本节与『契约变更』节同属『PROGRESS.md只写进度』铁律的结构化承载例外：它记录的是当前并发约束状态，不是过程档案。
