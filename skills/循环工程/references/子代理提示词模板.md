# 独立代理提示词模板

循环工程通过自然语言提示词派发独立代理，不绑定任何宿主的代理类型、工具名或参数格式。主代理把本模板交给宿主可用的独立代理能力；宿主不支持时，由主代理按同一规则串行补位。

## 派发前提

主代理必须提供：

- 当前功能点ID、目标和机器验收。
- 允许范围、非目标和用户WIP。
- 依赖及尚未吸收的契约增量。
- `headless_mode=true`。
- 推理门：`G2` 或 `无`；为 `G2` 时附 `references/推理增强.md` 要求的反例或不变量、迁移边界和隐藏验收场景。
- 修复、stall、轮次估算和宿主步骤限制；未知时明确写“未知”。
- 上一轮摘要、证据和“不要重做”清单；首次派发写“无”。

已核实事实和主代理推断必须分栏：

```text
## 已核实事实

- <文件行号、命令输出或源码证据>

## 主代理推断

- <需要独立代理先证伪的判断>
```

## 通用提示词

```text
你是循环工程的独立代理，只负责当前功能点。使用新上下文完成任务，完成后返回规定摘要，不向用户提问，不替主代理最终交付。

先读取项目规则、PROGRESS.md、当前功能点、范围边界、用户WIP和契约增量。不得扩展范围，不得覆盖用户WIP。

执行要求：

1. 先验证主代理推断；发现冲突立即停止并返回“待用户确认”。
2. 推理门为G2时，先按 `推理增强.md` 写出反例或不变量、迁移边界和隐藏验收场景的结论，再进入实现。
3. 按项目实际能力调用代码需求实现器、Bug修复、软件测试、三轴审查或方案审查。
4. 修改后运行适用的局部测试、构建、lint和审查。
5. 高危操作按EnvironmentEngineering.md用通俗语言说明并返回待确认，不直接执行。
6. 真实失败按 `BUDGET.md` 的 `per_fp_attempt_limit` 处理；中段换方法，达到上限后标阻塞。
7. 返回前回收自己启动的后台任务；无法回收时不得报告完成。
8. 不写PROGRESS.md，不返回完整代码、完整日志或无关文件清单。
9. 在步骤预算约70%时停止扩展，优先完成验证、证据和收尾。
10. 只返回“Worker 返回格式 v2”规定的字段。
```

## 任务类型补充

### 新功能

- 先写能失败的测试，再写最少实现使其通过，最后在测试保护下重构。
- 用户可见文本遵循项目翻译机制。

### Bug修复

- 先建立稳定复现，再定位根因。
- 搜索同类问题并处理同根因项。
- 运行复现测试、受影响测试和全量回归。

### 重构

- 先确认现有测试能保护当前行为。
- 不改变公开行为，不增加新功能。
- 每个小步后运行受影响门禁。

## 验证要求

每个功能点至少给出以下适用门禁：

1. 目标功能测试。
2. 受影响的构建或类型检查。
3. lint或静态检查。
4. 实施后三轴审查。
5. 方案或方向性改动的前置审查。

结果使用三态：

- 通过：所有适用门禁满足验收。
- 环境限制：宿主能力、网络、工具、用户WIP或外部环境导致无法完成；必须给出具体证据。
- 真实失败：实现、测试、构建或审查不满足要求；进入修复阶梯。

没有证据文件时使用“证据：无”，但“验证”字段必须包含命令和目标。

## 树状态与改动核验

独立代理必须报告：

- 本功能点实际修改的相对路径，最多5项；无修改写“无”。
- 返回时的树状态：`绿`、`红(<未绿门禁>)`或`已回滚`。
- 是否存在后台任务；存在时必须已回收，否则不能报告完成。

主代理不能只相信自报树状态，必须用实际文件、版本控制差异或快照哈希交叉核验。

## 并行规则

仅在无依赖、无文件冲突、无资源冲突时并行。派发提示词必须写明：

- 其他代理可能修改的范围。
- 禁止触碰的共享文件。
- 契约增量的旧值和新值。
- 共享门禁的持有者。

同一工作树同一时刻只允许一个代理持有共享构建、测试或lint门禁。

## Headless决策

遇到需求歧义、方向性假设、权限决定或高危操作时，返回：

```text
状态：待用户确认
问题：<需要决定的一件事>
背景：<为什么必须决定>
选项：<选项A；选项B>
推荐：<推荐项及理由>
影响：<对范围、风险和恢复的影响>
证据：<文件行号或命令输出>
恢复：<决定后从哪里继续>
```

不要调用用户交互能力，不要等待用户回复。

## Worker 返回格式 v2

每个字段独占一行，顺序固定，不输出额外正文：

```text
摘要版本：2
功能点：<ID> <简述>
状态：<已完成|已阻塞|已跳过|待用户确认>
结果：<完成、阻塞或待确认的一句话结果>
失败标签：<无或鉴权,网络,数据,逻辑,依赖,未知>
证据：<无或 .agents/evidence/ 下的真实文件路径>
验证：<通过|环境限制|真实失败>；命令=<命令>；目标=<目标>；结果=<结果>
计数：修复=<n>;stall=<n>;轮次=<n>;估算=<n>;宿主上限=<数值或未知>;嵌套=<n>
修改文件：<无或最多5个相对路径，逗号分隔>
树状态：<绿|红(...)|已回滚>
后台任务：<无后台任务|已回收|存活(...)>
审查：<通过|问题(...)|待主代理补位(...)>
遗留：<无或未解决问题>
前提证伪：<无或被证伪推断及证据>
契约变更：<无或类型；旧值到新值；消费者>
下一步：<交给主代理的一个明确动作>
```

## 返回约束

- `摘要版本`必须为2。
- `状态=已完成`时，验证必须为通过、树状态必须为绿、后台任务必须无存活项、审查必须通过且不能存在门禁缺口。
- 独立审查无法建立时，状态必须为`已阻塞`，审查写`待主代理补位(<缺失门禁>)`；禁止把主代理自审伪装成独立审查。
- `失败标签=无`时不得同时写其他标签；多个标签使用英文逗号分隔。
- `证据=无`时，验证必须同时包含命令和目标。
- `计数`中的修复和stall不能同时大于0，`估算`必须大于0；`嵌套`必须回报实际创建的嵌套代理实例数。
- `修改文件`只列当前功能点实际改动的相对路径，不是完整文件清单；禁止绝对路径、盘符、反斜杠和路径穿越。
- `遗留`必须包含恢复下一步；无遗留写“无”。
- 推理门为G2时，`前提证伪`或`证据`必须能看出反例或不变量、迁移边界和隐藏验收场景各自的处理结论。
- 字段缺失、重复、乱序或出现未知字段时，摘要无效。
