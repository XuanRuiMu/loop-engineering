# 前端验证技巧（实战坑 · 纯说明性）

> 来源：某前端项目 FP 修复任务（2026-08-12）Self-Harness 元循环挖掘。
> 修改级别：自动（新增纯说明性 references，不改动核心工作流）。

## 1. Windows 下 Playwright ESM 模块解析

- **症状**：截图/验证脚本放在项目子目录（如 `.workbuddy/scratch/`）时，`import { chromium } from 'playwright'` 报 `ERR_MODULE_NOT_FOUND`——脚本位置无法向上解析到项目根 `node_modules`。
- **错误尝试 1**：设 `NODE_PATH` 无效——ESM 不走 `NODE_PATH`。
- **错误尝试 2**：直接写绝对路径 `D:/.../node_modules/playwright/index.mjs` → 报 `ERR_UNSUPPORTED_ESM_URL_SCHEME`（Windows 绝对路径需带协议）。
- **正确做法**：用 `file:///D:/项目根/.../node_modules/playwright/index.mjs`（三斜杠 `file:///` + 绝对路径）。
- **更稳妥**：把验证脚本放在项目根目录（与 `node_modules`/`package.json` 同层），用裸 `import 'playwright'` 即可解析。

## 2. 当前主模型无法直接读 PNG 图像

- **症状**：用 Read 工具读取截图 PNG 时返回 `[System reminder: the current model does not support images...]`，主代理无法肉眼复核像素。
- **应对（用户硬性要求"必须截图检查"时）**：
  - 把视觉复核委托给 Task 子代理（Headless Worker 能读图并人眼复核），主代理信任其结构化摘要；
  - 主代理自身用 DOM/Canvas 测量作为代理证据：`getBoundingClientRect` / `offsetWidth` / `scrollHeight`、CSS 变量（如 `--note-fit`）、`<canvas>.getContext('2d').getImageData()` 像素扫描定位正文区与边界；
  - 若子代理已读图，主代理后续对**同一文件**再 Read 会返回 `Image unchanged, same content as when previously read`，可作为"已复核"的间接佐证。

## 3. GitHub 上传的环境约束（对应 EVIDENCE EV-004）

- 沙箱 bash 无 TTY，`github.com:443` 会间歇性 TCP 重置；子代理裸 `git push` 既可能卡交互式认证，也可能因网络抖动失败。
- 本项目统一走项目内推送封装（自带 token 注入 + 自动 `git pull` + `push -u origin HEAD`），禁止子代理裸 `git push`。
