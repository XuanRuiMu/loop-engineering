# 前端验证技巧（实战坑 · 纯说明性）

> 来源：某前端项目 FP 修复任务（2026-08-12）Self-Harness 元循环挖掘。
> 修改级别：自动（新增纯说明性 references，不改动核心工作流）。

## 1. Windows 下 Playwright ESM 模块解析（强制摆位）

- 验证脚本必须放在任务工作区内与 `node_modules`/`package.json` 同层（作用域合规，禁止放工作区根或 skill 目录外）；子目录脚本引用 playwright 用 `file:///D:/项目根/.../node_modules/playwright/index.mjs`（三斜杠 `file:///` + 绝对路径），ESM 不走 `NODE_PATH`。
- 截图输出一律落盘 `.agents/evidence/traces/<FP-ID>-<页面>-<YYYYMMDD>.png`，同名 `.md` 记录 DOM 指标；禁止只贴图不落盘。

## 2. 截图落盘为主、读图复核为辅（含无图模型降级）

- 前端FP验收以落盘截图 + DOM 文本断言为机器证据，读图复核只作可选加分；主代理只认子代理结构化摘要，不做肉眼终审。
- 模型无读图能力时，以 DOM 文本断言放行，禁止以"看不到图"判阻塞；子代理已读图时，主代理对同一文件再 Read 返回 `Image unchanged` 可作已复核佐证。
- 沿用 DOM/Canvas 代理证据：`getBoundingClientRect` / `offsetWidth` / `scrollHeight`、CSS 变量、`<canvas>.getContext('2d').getImageData()` 像素扫描。

## 3. GitHub 上传的环境约束（对应 EVIDENCE EV-004）

- 沙箱 bash 无 TTY，`github.com:443` 会间歇性 TCP 重置；子代理裸 `git push` 既可能卡交互式认证，也可能因网络抖动失败。
- 本项目统一走项目内推送封装（自带 token 注入 + 自动 `git pull` + `push -u origin HEAD`），禁止子代理裸 `git push`。

## 4. 控制台过滤（只拦 error，放行 warning）

- 前端验收的控制台门只统计 `error`，`warning` 一律放行；多页 pops/异步日志先在 FP 验收标准里写明白白名单，无白名单定义时不得以 warning 判失败。

## 5. DOM 必填指标与写入位置

- 每个前端FP的同名 `.md` 必须含：页面 URL、视口尺寸、关键容器 `getBoundingClientRect`、有无横向溢出、过滤后控制台 error 计数；缺任一项视为证据不全。

## 6. 全量测试 flaky 三段判定与文件级隔离（2026-09-17 个人简历任务实战）

- 全量失败但单文件恒过时，禁止直接判业务回归：先基线对照（`git stash` 隔离本任务改动重跑，基线同样失败即既有 flaky），再串行复核（单文件/双文件组合跑确认业务逻辑过），最后隔离修复（只改测试不动业务）。
- 多 `render` 同一组件的测试文件必须加 `afterEach(cleanup)`；长耗时跑马灯/物理引擎用例按需提 `timeout`；短标题正则跨组件污染时限定查询容器（`within`）或收紧为全匹配。

## 7. 视觉验收必须是独立工人，且不与实现混派（2026-09-19 十四项缺陷修复任务实战）

- 反例：把"修一个线上 500"与"8 项浏览器取证"混派给同一工人，两个目标互相挤占轮次，双双未收口，且主代理无法判断哪一段先做完。
- 规则：取证/验收一律单独派发；单工人验收面 ≤3 个；实现工人只负责"改前/改后截图 + DOM 断言"这类最小证据，跨页面多视口的完整取证交给验收工人。
- 派发给验收工人的提示词要控制体量：过长的单次提示词会被模型服务直接拒绝（现象为 `The model service rejected this request`），此时不是任务失败而是投递失败——拆短重派，不要据此判功能阻塞。
